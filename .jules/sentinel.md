## 2024-05-15 - Unrestricted File Upload and Stack Trace Leak in Streamlit UI
**Vulnerability:** The application allowed arbitrary file uploads via `st.file_uploader` without restricting extensions, and buttons to process those files lacked checks for `None`, leading to unhandled exceptions and stack trace leaks if clicked prematurely.
**Learning:** In Streamlit applications, failing to restrict `st.file_uploader` extensions (`type`) or leaving UI components active when their dependencies (like uploaded files) are missing can result in both malicious file execution/storage risks and unintentional data leakage through error stack traces.
**Prevention:** Always restrict `st.file_uploader` extensions using the `type` parameter, and use the `disabled` parameter on interactive elements like `st.button` to prevent them from executing invalid states when dependencies are missing.
## 2024-05-24 - Missing Null Check and Stack Trace Leak in Streamlit UI
**Vulnerability:** A missing null check on the uploaded file (`test_image is not None`) before processing it via the `Predict` button could lead to unhandled exceptions. If triggered, this could result in a stack trace leak, potentially exposing internal implementation details.
**Learning:** In Streamlit, UI interactions (like button clicks) should not assume dependencies (like an uploaded file) are present just because a `disabled` state was used (which might be bypassed or incorrectly initialized). Any data processing must explicitly check for the presence of the data, and handle any potential exceptions gracefully to avoid leaking stack traces to the end user.
**Prevention:** Explicitly check for `None` before processing variables derived from user input. Always wrap backend processing logic (such as model predictions) in `try...except` blocks and display generic error messages via `st.error` to mask the internal exceptions.
